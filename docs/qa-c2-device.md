> 자동 측정과 개선은 끝났고, **아래 2장 실기기 확인이 남았습니다.** 다 끝나면 타임라인에서 C2를 완료 체크해 주세요.

## 1. 자동 측정 (헤드리스 Chromium)

- 방법: `npm run build && npm start`(데모 모드) 후 `node scripts/perf-measure.mjs --cpu 6`. 375×667 @2x, CPU 4배·6배 스로틀, 진입 애니메이션이 끝난 뒤 6초.
- 한계: GPU 없는 소프트웨어 렌더링이고 한 번씩만 잰 값이라 ±15% 정도 흔들립니다. 절대값이 아니라 **같은 환경의 전/후 비교**로만 보세요. GPU 메모리·발열·배터리는 잴 수 없어 실기기에서 확인합니다.
- `메인` = 메인 스레드가 1초에 일한 시간(ms, 1000이면 꽉 참), `래스터` = 픽셀을 다시 그린 시간(ms/초), `프레임` = 메인 스레드가 1초에 만든 프레임 수.

| 화면 | 메인 4x 전 → 후 | 메인 6x 전 → 후 | 래스터 6x 전 → 후 | 프레임 전 → 후 |
| --- | --- | --- | --- | --- |
| `/t/demo` | 158 → 91 | 274 → 163 | 0 → 0 | 60 → 33 |
| `/t/demo?dday=0` (전구 전부·무지개) | 345 → 122 | 425 → 223 | 227 → 0 | 60 → 37 |
| `/t/demo?fill=60` | 206 → 150 | 341 → 205 | 0 → 0 | 60 → 39 |
| `/t/demo/write` | 102 → 88 | 184 → 143 | 0 → 0 | 60 → 30~37 |
| `/` | 194 → 98 | 293 → 197 | 0 → 0 | 60 → 36 |

- 전/후 모두: 끊긴 프레임 없음(rAF 간격 p95 16.7ms), 50ms 넘는 긴 작업 0개, 레이아웃 0, JS 힙 3~5MB.
- "동작 줄이기"를 켠 상태(후): 모든 화면에서 메인 스레드 일 0~16ms/초 (계속 도는 애니메이션 없음).

### 병목과 고친 것
| 병목 (측정으로 확인) | 고친 것 | 보이는 차이 |
| --- | --- | --- |
| 눈 캔버스가 매 프레임(60fps) 화면을 다시 합성하고, 그때마다 다른 애니메이션의 스타일 계산도 같이 돎 — 평상시 비용의 절반 이상 | `Snow.tsx`: 초당 30번만 그림(쉬는 프레임엔 rAF도 안 걺), 눈송이를 한 번에 칠함, 탭이 가려지면 정지, 동작 줄이기면 멈춘 눈 | 눈이 아주 약간 덜 매끄러움. 속도는 같음. `FPS` 상수 하나로 되돌릴 수 있음 |
| 12/25 무지개: 전구 24개의 색을 매 프레임 바꾸며 blur 필터(`feGaussianBlur`)를 다시 그림 — 래스터 227ms/초 | `TreeScene.tsx`: 전구를 SVG 밖 HTML로 옮기고 빛 번짐은 `box-shadow`. 무지개는 색을 한 칸씩 민 전구 묶음 4장을 opacity로 번갈아 보여 줌 | 빛 번짐은 거의 같음. 무지개는 색이 이어서 섞이는 대신 0.5초 머물고 0.25초에 바뀜. 이웃 전구끼리 색이 항상 다름 |
| D-7부터 별 `twinkle`이 `drop-shadow` 필터를 매 프레임 다시 그림 (6x에서 약 200ms/초) | 약한 빛은 고정, 강한 빛 복사본의 opacity만 움직임 | 거의 같음 |
| (접근성) 동작 줄이기에서도 흔들림·깜빡임이 계속 돎 | `globals.css`: 흔들림·전구·별·무지개 정지 | 동작 줄이기를 켠 사람만 |

- 고치지 않은 것: 장식 `ornament-sway`(이미 합성 단계에서 돌고, 눈을 30fps로 낮추자 스타일 계산도 절반이 됨), 트리 그림자 `#soft`(전구가 SVG에서 빠져 다시 그려지지 않음), 눈 캔버스 해상도(원래 CSS 픽셀 1배라 devicePixelRatio 상한이 필요 없음).
- 못 잰 것: 무지개 때 전구 묶음 레이어 4장의 GPU 메모리(레이어를 전구 띠 크기로 줄여 3배율 폰 기준 대략 10~15MB로 추정), 실제 발열·배터리.

## 2. 실기기 체크리스트 (사람 몫)

**준비** — 데모 배포 `https://decorate-my-trea-demo.vercel.app` (이 브랜치가 배포된 뒤). 주소 뒤에 붙이는 것: `?dday=N`(연출), `?fill=60`(장식 60개), `&added=1`(편지를 막 단 상태).

**기기** — 가능한 만큼. 최소 ①②③.
| # | 기기 | 브라우저 |
| --- | --- | --- |
| ① | 최근 아이폰 | Safari |
| ② | 최근 안드로이드 | Chrome |
| ③ | 저사양·오래된 폰 (3년 이상 된 보급형 안드로이드, 또는 아이폰 8·SE급) | 기본 브라우저 |
| ④ | 작은 화면 (아이폰 SE 1세대 등 320px 폭) | Safari |

**A. 애니메이션 끊김** (각 화면 30초씩 보고, 위아래로 스크롤도 해 보기)
- [ ] `/t/demo` — 눈이 끊기지 않고 내리는지, 장식 흔들림이 부드러운지
- [ ] `/t/demo?dday=7` — 별이 은은하게 빛났다 줄었다 하는지, 전구가 깜빡이는지 (꺼진 전구는 회색)
- [ ] `/t/demo?dday=0` — 전구 24개가 다 켜지고 색이 돌아가며 바뀌는지, 바뀌는 순간 깜빡거리거나 뚝뚝 끊기지 않는지, 전구 위치가 줄에서 벗어나지 않는지
- [ ] `/?dday=0` (홈), `/t/demo/write` — 눈·트리 끊김 없는지
- [ ] `/t/demo?dday=7`에서 별 7번 빠르게 탭 — 전구가 차례로 흐르고 썰매가 지나가는지, 끝나면 원래대로 돌아오는지
- [ ] 포닉스 탭 — 레드 트리로 바뀔 때 끊김 없는지
- [ ] 화면을 가로로 돌렸다 세로로 — 눈이 화면 전체에 다시 내리는지

**B. 트리 넘김** (`/t/demo?fill=60`, 규칙은 `spec.md` 5.1 — C3가 남긴 항목)
- [ ] 트리 위에서 좌우로 밀면 넘어가고, 세로 스크롤은 그대로 되는지
- [ ] 화면 왼쪽 가장자리에서 민 스와이프가 브라우저 "뒤로 가기"로 빠지지 않는지. 겹치면 ◀ ▶ 버튼으로 넘어가는지
- [ ] 스와이프 끝이 장식 위여도 잠금 안내가 뜨지 않는지
- [ ] 처음/◀/▶/최신 버튼이 누르기 충분하고 320px 폭에서 한 줄인지 (④)
- [ ] `&added=1` — 마지막 트리가 열리고 새 장식이 톡 튀어나오는지
- [ ] 저사양 폰(③)에서 넘길 때 끊김 없는지

**C. 편지 쓰기·키보드** (`/t/demo/write`)
- [ ] 닉네임·본문 입력창을 누르면 키보드가 입력창과 "다음"/"보내기" 버튼을 가리지 않는지 (가리면 스크롤로 보이는지)
- [ ] 키보드가 올라온 동안 눈·화면이 떨리거나 튀지 않는지
- [ ] 보내고 나서 트리로 돌아와 폭죽·새 장식이 나오는지

**D. 절전·동작 줄이기·백그라운드**
- [ ] 저전력 모드(iOS) / 절전 모드(Android)를 켜고 A를 다시 — 느려져도 화면이 깨지거나 멈추지 않는지
- [ ] 동작 줄이기(iOS: 설정 > 손쉬운 사용 > 동작) / 애니메이션 삭제(Android: 설정 > 접근성)를 켜고 `/t/demo?dday=0` — 눈·흔들림·전구·별이 멈춘 채 보이는지, 트리 넘김이 바로 바뀌는지, 탭 반응(별·포닉스·토스트)은 되는지
- [ ] 다른 앱에 갔다가 1분 뒤 돌아오기 — 눈이 한꺼번에 쏟아지거나 멈춰 있지 않은지

**E. 발열·배터리** (③ 저사양 폰 위주)
- [ ] `/t/demo?dday=0`을 5분 켜 두기 — 폰이 뜨거워지는지, 배터리가 눈에 띄게 줄어드는지 (시작·끝 %를 적기)
- [ ] 5분 뒤에도 스크롤·탭이 처음처럼 반응하는지

**F. 접근성** (C3가 남긴 항목)
- [ ] VoiceOver·TalkBack에서 "이전 트리"/"다음 트리" 버튼과 "트리 4개 중 2번째 트리"가 읽히는지. 전구는 읽히지 않아야 함

> 인스타·카톡 인앱 브라우저, 스토리용 이미지 저장은 C1에서 확인합니다. 단 이번에 전구·별 구조가 바뀌었으므로 **이미지 저장 한 번은 다시** 해 봐 주세요: `/t/demo?dday=0`(주인 화면은 PR #6의 `?owner=1`)에서 저장한 이미지에 전구와 별의 빛이 찍히는지.
